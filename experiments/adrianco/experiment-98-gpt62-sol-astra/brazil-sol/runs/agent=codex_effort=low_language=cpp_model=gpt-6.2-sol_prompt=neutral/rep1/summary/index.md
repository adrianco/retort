## Interfaces

- **Transport (`main.cpp`)** — line-delimited JSON-RPC. `dispatch()` validates the
  envelope, routes methods, and for `tools/call` performs schema-driven argument
  validation (type checks + required fields) against each tool's `inputSchema`
  before delegating to `Graph::call`.
- **Facade (`Graph`)** — `call(tool, args)` dispatches to eight tools:
  `search_matches`, `team_stats`, `head_to_head`, `search_players`,
  `team_profile`, `competition_data`, `analyze_matches`, `dataset_coverage`.
- **`Graph::tools()`** — builds the MCP tool manifest (schemas, enums, pagination).

## Data flow

1. **Ingest (constructor)** — reads six CSVs from `data/kaggle/` (`Brasileirao_Matches`,
   `novo_campeonato_brasileiro`, `Brazilian_Cup_Matches`, `Libertadores_Matches`,
   `BR-Football-Dataset`, `fifa_data`). A custom quote-aware CSV reader (`csvRecord`)
   feeds row consumers.
2. **Normalize/merge** — `normalize()` (utf8proc casefold/decompose/stripmark) and
   `teamKey()` canonicalize team names across sources via an alias/state table;
   duplicate fixtures across datasets are detected and merged (scores, stats, sources).
3. **Index** — matches sorted newest-first; per-team fixture and squad index built;
   players sorted by overall rating; cup knockout stages inferred.
4. **Query** — `select()` is the shared match filter (team/venue/competition/season/
   date range/stage/round/status/derbies); `searchPlayers()`, `competition()` (standings/
   bracket/schedule), and `analyze()` (summary/biggest_wins/season_trends/team_rankings)
   build on it. Every list response is paginated via `page()`.

## Notable characteristics

- Standings, records, head-to-head and aggregate stats are **computed** from the
  merged match data, not hardcoded.
- Heavy dataset-specific curation (team aliases, state defaults, derby groups,
  per-season team counts, pandemic-season date cutoffs) — accurate for these
  datasets but tightly coupled to them.
- Single 934-line translation unit for the whole data/query layer.
