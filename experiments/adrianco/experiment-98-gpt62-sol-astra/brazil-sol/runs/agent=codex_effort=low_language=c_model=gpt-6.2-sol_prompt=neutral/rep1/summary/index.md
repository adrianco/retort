# Architecture Summary — Brazilian Soccer MCP Server (C)

A single-binary, stdio JSON-RPC 2.0 MCP server in C11, built on **GLib** (containers,
UTF-8, dates) and **json-c** (JSON I/O). Three translation units plus one header.

## Modules

| File | LOC | Responsibility |
|------|-----|----------------|
| `soccer.h` | 50 | Shared types (`Team`, `Match`, `Player`, `Database`), enums for competitions/sources, public API. |
| `mcp.c` | 148 | JSON-RPC transport + protocol: `main` read loop over stdin, strict tokenizer, `initialize`/`ping`/`tools/list`/`tools/call` dispatch, error envelopes (`-32700/-32600/-32601/-32602`). |
| `data.c` | 538 | CSV ingestion + normalization: streaming RFC-4180 parser (`csv_record`), team-name normalization/aliasing/state-suffix logic (`normalize`, `team_key`), multi-format date parsing, cross-source match de-duplication (`merge_matches`), cup-final tagging. |
| `queries.c` | 828 | 8 MCP tools, their JSON input schemas, argument validation, filtering, aggregation (records, standings, head-to-head, season stats), player search + club rating rollups, pagination. |

## Data flow

1. `database_load` reads all six CSVs from `data/kaggle/` into `db->raw` (matches) and
   `db->players`; teams are interned in `db->teams` (keyed by normalized name).
2. `mark_cup_finals` labels Copa do Brasil finals; `merge_matches` builds a combined,
   de-duplicated fixture view (`db->matches`) that unions provenance across sources and
   backfills missing scores/dates/stadiums.
3. The stdin loop parses one JSON-RPC request per line and dispatches to `tool_call`,
   which validates args against the tool's schema, builds a `Filter`, selects matches,
   and serializes results (with `structuredContent` + text mirror).

`search_matches`, `team_stats`, `standings`, `search_players`, `competition_stats`,
`club_profile`, `top_scorers`, `data_coverage` — covering all five required query
categories plus cross-file joins and a data-coverage probe.
