# Architecture summary — brazilian-soccer-mcp (Swift)

A dependency-free Swift Package (`swift-tools-version:5.9`) implementing an MCP
server over stdio for a Brazilian-soccer knowledge base assembled from six Kaggle
CSV files.

## Layout

- **`Sources/brazilian-soccer-mcp/main.swift`** — executable entry point. Locates
  `data/kaggle`, builds the `DataStore`, and either (a) serves MCP line-by-line over
  stdio, or (b) runs one tool via `--call <tool> '<json>'`.
- **`Sources/BrazilianSoccerCore/`** — the library target:
  - `DataStore.swift` — loads and de-duplicates the six CSVs into an in-memory model
    (normalised teams, merged matches, FIFA players); `locateData` path discovery.
  - `Models.swift` — `Match`, `Player`, `Competition`, `Record`, `Day`, `Venue`, etc.
  - `Support.swift` — CSV parsing (`CSVTable`), text folding, team-name normalisation.
  - `Teams.swift` — `TeamRegistry` resolving many spellings to one club key.
  - `Queries.swift` — filtering, league table/standings, head-to-head, knockout-tie
    aggregation, player search.
  - `Tools.swift` — the 16 MCP tools: argument coercion + plain-text answers.
  - `MCPServer.swift` — JSON-RPC 2.0 dispatch: `initialize`, `ping`, `tools/list`,
    `tools/call`, `resources/list`, `prompts/list`.

## Data flow

CSV files → `DataStore` (parse → normalise teams → dedupe matches → infer seasons/
stages → load FIFA players) → `SoccerTools` (16 tools over `DataStore` query layer) →
`MCPServer` (JSON-RPC transport).

## Tests

`Tests/BrazilianSoccerCoreTests/` — 51 XCTest scenarios (Given/When/Then style) run
against the **real** CSV files via a shared `Fixture`. Cover data loading, dedup,
team-name resolution, each query category, standings/knockout correctness, the MCP
protocol handshake, and performance ceilings. 0 failures, 0 skips.
