# Book collection API

Python 3.10+ service using Flask and the standard-library SQLite driver.

## Setup and run

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

The development server listens at `http://127.0.0.1:5000`. The database and
schema are created automatically in `books.sqlite3` beside `app.py`. To use
another file, set `BOOKS_DATABASE=/path/to/books.sqlite3` (its parent directory
must already exist). Data survives restarts. Flask's development server is
intended for local use.

## API

| Method | Path | Response |
| --- | --- | --- |
| POST | `/books` | Created book, 201 and `Location` header |
| GET | `/books` | Array of books ordered by ID, 200 |
| GET | `/books?author=Frank%20Herbert` | Exact, case-sensitive author match, 200 |
| GET | `/books/{id}` | Book, 200; 404 if absent |
| PUT | `/books/{id}` | Replaced book, 200; 404 if absent |
| DELETE | `/books/{id}` | Empty response, 204; 404 if absent |
| GET | `/health` | `{"status":"ok"}`, 200 after a database connectivity check |

POST and PUT accept a JSON object with required nonblank string `title` and
`author`. Both are trimmed. Optional `year` is an integer from 1 to 9999 or
null; optional `isbn` is a nonblank string or null, stored trimmed without
checksum validation. Unknown fields are rejected. PUT replaces all fields;
omitted optional fields become null. IDs are generated by the service.

Invalid input returns 400 with `{"error":"..."}`. Routing errors also return
JSON; database operation failures return 503. All successful responses are
JSON except the empty 204 deletion response.

```sh
curl -i http://127.0.0.1:5000/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"Dune","author":"Frank Herbert","year":1965,"isbn":"9780441172719"}'
curl http://127.0.0.1:5000/books
```

## Tests

```sh
python -m unittest discover -v
python -m compileall -q app.py test_app.py
```

Tests use isolated temporary SQLite files and Flask's HTTP test client, covering
CRUD, validation, filtering, missing resources, health, and persistence across
application instances.
