# Book collection API

Python 3.10+ service using Flask and the standard-library SQLite driver.

## Setup and run

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

The service listens on http://127.0.0.1:5000. Set `PORT` to change the port.
SQLite tables are created automatically in `books.db` in the working directory.
Set `BOOKS_DATABASE` to use a different database file (its parent directory must
exist). Data persists between restarts. The built-in server is for local use;
a WSGI server can load the `app:create_app()` application factory for deployment.

## API

| Method | Path | Result |
| --- | --- | --- |
| POST | `/books` | Create a book: 201, book JSON, and Location header |
| GET | `/books` | 200, array of books ordered by ID |
| GET | `/books?author=An%20Author` | 200, exact, case-sensitive author matches |
| GET | `/books/{id}` | 200, book JSON; 404 if missing |
| PUT | `/books/{id}` | Replace a book: 200, updated JSON; 404 if missing |
| DELETE | `/books/{id}` | 204, empty body; 404 if missing |
| GET | `/health` | 200, `{"status":"ok"}` after checking database connectivity |

POST and PUT require a JSON object with non-blank string `title` and `author`.
Optional `year` must be an integer from 1 to 9999 or null. Optional `isbn` must
be a non-blank string or null; ISBN checksums and uniqueness are not enforced.
Strings are trimmed. Unknown fields are rejected. PUT requires both required
fields and resets omitted optional fields to null. IDs are generated by SQLite.
Invalid fields or malformed JSON return 400; non-JSON request bodies return
415. HTTP errors return `{"error":"description"}`.

```sh
curl -i http://127.0.0.1:5000/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"A Book","author":"An Author","year":2020,"isbn":"0012345678"}'
curl 'http://127.0.0.1:5000/books?author=An%20Author'
```

## Tests

```sh
python -m unittest discover -v
python -m compileall -q app.py test_app.py
```

Tests use isolated temporary SQLite files and cover CRUD, filtering, validation,
HTTP errors, health checks, and persistence across application instances.
