# Book collection API

A Swift Package Manager service backed by SQLite, with no third-party package dependencies.

## Setup and run

Install Swift 5.9 or newer and SQLite development headers (on Debian/Ubuntu, `libsqlite3-dev`; on macOS, the Xcode command-line tools). From this directory:

```sh
swift build
swift test
swift run book-server
```

The server listens on port 8080 on all interfaces. Set `PORT` to change the port and `DATABASE_PATH` to change the SQLite database file (default: `books.sqlite` in the current directory). For example:

```sh
PORT=3000 DATABASE_PATH=/tmp/books.sqlite swift run book-server
```

## API

All responses are JSON. `title` and `author` must be non-empty strings after trimming whitespace; `year` (integer) and `isbn` (string) are optional and may be null. PUT replaces all fields, so omitted optional fields become null. IDs are positive integers generated by SQLite. Author filtering uses an exact, case-sensitive match.

- `GET /health` — returns `{"status":"ok"}`.
- `POST /books` — create a book; returns 201 and the created object.
- `GET /books` — return an array ordered by ID. Use `?author=...` to filter.
- `GET /books/{id}` — return one book.
- `PUT /books/{id}` — replace a book and return it.
- `DELETE /books/{id}` — delete a book and return a confirmation.

Missing books and unknown paths return 404, invalid input returns 400, and unsupported methods on book routes return 405. Errors have the form `{"error":"..."}`.

```sh
curl -X POST http://localhost:8080/books -H 'Content-Type: application/json' \
  -d '{"title":"Dune","author":"Frank Herbert","year":1965,"isbn":"9780441172719"}'
curl 'http://localhost:8080/books?author=Frank%20Herbert'
curl http://localhost:8080/health
```
